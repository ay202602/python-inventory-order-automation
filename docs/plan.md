# 設計・開発計画

CLAUDE.md には常時守る規則のみを置き、背景・仕様・進捗はここに書く。

## DB（3テーブル）
- `suppliers`(id, 名前) / `items`(id, 名前, supplier_id, 発注点, 発注単位) / `stock_movements`(id, item_id, 日付, 数量)
- 現在庫は列に持たず `stock_movements` の SUM で計算（入庫は＋、出庫は−）。
- 1備品につき発注先は1社固定。在庫は常に最小単位（本）で管理する。
- 発注数量 = 不足数を発注単位で切り上げ。
- SQLで集計できることはSQL、複雑な加工はPython。判断が分かれたらREADMEの設計意図に理由を書く。

## 作らない機能
発注状態管理・発注残・一括取込・グラフ・複数発注先。
「発注書を出しても入荷登録までは不足一覧に残り続ける」はREADMEの「既知の制限」に明記する。

## Excel出力
- クラウド上ではファイル保存してもユーザーに届かない。`BytesIO` でメモリ上に作り `st.download_button` で渡す。
- 雛形Excelを1枚固定で `load_workbook` し、セルに値を書き込む。発注先ごとに作成する。
